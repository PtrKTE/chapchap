5.3 AMÉLIORATION : CALCUL DU COÛT UNITAIRE PAR PRODUIT
───────────────────────────────────────────────────────
PROBLÈME INITIAL :
  Le coût unitaire était identique pour tous les produits (répartition égale
  par quantité). Ex : gésier = escalope = intestin → économiquement faux.

ANCIENNE FORMULE :
  cout_par_unite = cout_total_entrant / sum(toutes quantités)
  → Même coût pour 1 gésier que pour 1 escalope.

NOUVELLE FORMULE (répartition par valeur marchande) :
  valorisation_ligne   = quantite_effective × prix_vente_defaut
  total_valorisation   = sum(valorisation_ligne pour toutes les lignes)
  cout_absorbe_ligne   = (valorisation_ligne / total_valorisation) × cout_total_entrant
  cout_unitaire_ligne  = cout_absorbe_ligne / quantite_effective

  Résultat : les escalopes (3 800 FCFA/kg) absorbent plus de coût que les
  intestins (500 FCFA/kg). Cohérent avec la réalité économique.

GESTION DE LA QUANTITÉ EFFECTIVE :
  Depuis l'ajout de quantite_unite, certaines lignes n'ont pas de kg.
  quantite_effective = quantite (kg) si > 0, sinon quantite_unite (pièces)

5.4 CORRECTION : CALCUL DU RENDEMENT
─────────────────────────────────────
PROBLÈME INITIAL :
  Le rendement affichait 687% → formule basée sur valorisation financière avec
  des quantités en unités traitées comme si elles pesaient 1 kg chacune.

EXPLICATION DU BUG :
  963 gésiers × 2 500 FCFA/kg = 2 407 500 FCFA (calculé)
  alors que la vraie valeur = 963 × 0,034 kg × 2 500 = 81 742 FCFA
  → Gonflé 29× car on traitait chaque pièce comme 1 kg.

DISCUSSION :
  Deux types de rendement expliqués :
    - Rendement poids   : poids_sortie / poids_entrée → standard industrie avicole
    - Rendement financier : valorisation_vente / coût_achat → sensible aux unités

DÉCISION : rendement poids (Option A avec saisie manuelle des kg).

NOUVELLE FORMULE :
  poids_obtenus = sum(quantite en kg des lignes où quantite > 0)
  poids_entrant = poids_total_entrant (saisi dans le formulaire)
  rendement     = poids_obtenus / poids_entrant

  Si poids_entrant = 0 ou poids_obtenus = 0 → rendement = null (non calculable)
  Exemple : 1 082 kg produits / 1 444,5 kg entrants = 74,9 %

CONDITION POUR AVOIR LE RENDEMENT :
  1. Renseigner "Poids moyen entrant" → poids total calculé automatiquement
  2. Renseigner "Quantité (kg)" sur les lignes produits (pas uniquement les unités)

9. POINTS D'ATTENTION TECHNIQUES
================================================================================

- MySQL MAMP fonctionne via socket uniquement (skip_networking=ON).
  Toujours utiliser DB_SOCKET dans .env et phpunit.xml.

- Filament Repeater avec ->relationship() : les champs virtuels (->dehydrated(false))
  ne sont pas sauvegardés en base → nb_effil_form et nb_pac_form sont virtuels.

- quantite_effective : dans la validation d'une production, on utilise quantite (kg)
  si renseigné, sinon quantite_unite (pièces). Sans kg sur les lignes, le rendement
  sera null.

- montant_facture dans les lots est auto-rempli par calculerTotaux() mais reste
  modifiable. Si l'utilisateur saisit manuellement une valeur différente, elle
  est conservée.

- Inventaire : le CMP utilisé pour le résumé des ajustements est le CMP actuel
  de stock_emplacements au moment de la consultation (pas le CMP au moment de
  la validation). Légère approximation acceptable.
