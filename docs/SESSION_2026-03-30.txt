2. FIX MODULE INVENTAIRE — ÉCARTS INCORRECTS (= 0)
================================================================================

PROBLÈME CONSTATÉ EN PRODUCTION :
  Tous les écarts affichaient 0,000 dans la vue détail (infolist),
  même quand stock_physique ≠ stock_theorique.
  Ex : Poulet effilé → Théorique 350 / Physique 400 → Écart affiché : 0,000

CAUSE RACINE :
  1. Le bouton "Charger tous les produits" initialise ecart = 0 dans le Repeater.
  2. L'afterStateUpdated sur stock_physique calcule l'écart côté client (Livewire),
     mais si la réactivité ne se déclenche pas correctement, la valeur reste 0.
  3. L'infolist lisait directement la colonne `ecart` de la DB (valeur stockée = 0).
  4. La méthode validerInventaire() utilisait aussi $ligne->ecart (valeur DB).

CORRECTIONS APPORTÉES :

  A) InventaireResource.php — Infolist
     - TextEntry::make('ecart') remplacé par TextEntry::make('ecart_calcule')
     - getStateUsing() calcule dynamiquement : round(physique - theorique, 3)
     - Section "Résumé des ajustements" : tous les calculs (pertes/gains/impact/count)
       passent par round(stock_physique - stock_theorique, 3) au lieu de $ligne->ecart

  B) EditInventaire.php
     - validerInventaire() : vérification justifications et calcul écarts par
       round(stock_physique - stock_theorique, 3) au lieu de $ligne->ecart
     - Ajout mutateFormDataBeforeSave() : recalcule et persiste ecart avant chaque save

  C) CreateInventaire.php
     - Ajout mutateFormDataBeforeSave dans mutateFormDataBeforeCreate() :
       recalcule ecart = physique - theorique pour chaque ligne avant création

PRINCIPE RETENU :
  L'écart est toujours recalculé dynamiquement depuis physique - theorique.
  La colonne `ecart` en DB reste cohérente grâce à mutateFormDataBeforeSave,
  mais n'est jamais utilisée comme source de vérité pour l'affichage.
